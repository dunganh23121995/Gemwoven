# Gemwoven development

- Draw images through `codex_image_gen.py`: the OpenAI API credit (`gpt-image-2.5-sunburst`, quality low first) draws first, Codex when the credit is used up or the rung is 4+ (one shared ladder, rules in the owner's global CLAUDE.md, "Image generation: two backends"). Deep image processing and every review stay on Codex; the API key only draws. Climb only when the result fails review. Keep mechanics, feature design, integration, and ordinary coding on the current model.
- Read the imagegen and applicable sprite skills before generating. Use built-in ImageGen; keep final assets and prompts in this repository. Preserve original raw sheets for reproducibility.
- Start a new account with Hiro only. Premium Đá Ngọc must never be awarded from gameplay, daily quests, offline accumulation, summons, or the event editor. Payment processing is a future server feature.
- Chapter elites fight as drawn (range, body sheets, a boss-staged first skill with art and sounds of their own): `docs/ELITE_SKILLS.md`. Boss kits stay exclusive to their boss, with one exception: a chapter's last elite plays its boss's ultimate on stage 45.
- Progression rules are shared by the hub and combat through `src/gemwoven/progression.js`. Avoid duplicating economy calculations in UI code.
- Keep unreleased features clearly marked Coming soon. Local PvP is not online PvP; local records are not global leaderboards. The event studio is a local configuration prototype, not an authenticated production admin.
- Keep generated hub HTML, ZIPs, QA images, dependency folders, and temporary reports out of Git. `Game.html` is an existing tracked entry point; preserve its current repository convention. Commit useful source art, runtime assets, source, tests, and dependency locks.
- No unused pictures in the repository (owner 08/11): keep only what the game or a build uses, the raw sheets and prompts it was drawn from, masters and rig sources (part maps, resting frames), and per-frame files an fx export reads. When a redraw replaces art, delete in the same change the old sheet, its loose frames, "old" copies, rejected tries, QA images and any script that only served them. Before deleting, check the builds' own reads (`build.py` globs such as `creatures/*/idle.webp`, the `old.webp` beside a sharpened foe sheet) and paths the runtime builds by name (`'assets/combat-status/'+id`, `gem-${k}.webp`); `Game.html` must rebuild byte-identical.
- Rebuild combat with `python build.py`; rebuild the hub with `python scripts/build_gemwoven.py --quick` (only when art, sound or `copy.json` changed: the Studio loads `src/gemwoven/*` directly; owner 08/11). The full run (offline HTML + UI kit ZIP) only for an export. Run `npm test` in `qa/gemwoven/runtime` after mechanics changes.
- Foes rest and take buffs in baked mesh rigs too: a new creature, elite or boss needs `python assets/gemwoven/rig_foes.py parts <id>` then `make <id>`; without a rig folder it falls back to its drawn sheets. Its resting frame is then redrawn crisp at the size combat shows it (512px, bosses 640px): `python assets/gemwoven/sharpen_foes.py draw <id>`, `rig <id>`, `fidgets <id>` (`audit` measures every foe against the heroes).
- New heroes, and new items for every hero, follow `docs/HERO_PIPELINE.md`; the checklist `docs/hero-checklist.json` (run `python scripts/hero_checklist.py`) feeds the hero studio's "Hạng mục tướng" grid.
- Growth, economy, live-ops and arena design lives in `docs/GAME_DESIGN.md` (Studio tab "Thiết kế hệ thống"); live-ops numbers in `src/gemwoven/liveops.js`. Measure balance changes with `node qa/gemwoven/balance-sim.cjs` before and after.
- After adding runtime art or sound, refresh the download packs with `node scripts/build_asset_packs.cjs` (`assets/packs.json`; `src/gemwoven/asset-packs.js` picks packs per account).
- The plaza (Trò Chuyện) talks to the social server `server/social` (Node + ws, port 8091; `npm install && npm test` there); shared rules in `src/gemwoven/social-protocol.js`, protocol in `docs/SOCIAL_PROTOCOL.md`. Contested design waits until Claude and Codex agree (`docs/GAME_DESIGN.md` §20); `docs/REQUEST_TRACKER.md` answers each owner request.
- Every new or rebuilt screen gets a design review, not only a size/bug checklist: Codex critiques it against the approved screens, draws a mockup with image_gen that both agree on before coding, the build uses drawn art (not plain CSS boxes), and Codex scores the result against the mockup on a phone viewport and in the Studio page (`tools/studio.html`, Game (Hub), 1920×911) until it passes (≥ 8/10). Example: `assets/gemwoven/raw/forge-mockup/`.
